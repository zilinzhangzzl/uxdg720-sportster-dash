# Sportster S 仪表盘交互原型

模拟摩托车数字仪表的可操作网页原型。重点是页面、按钮、状态变化和弹窗逻辑，不还原品牌视觉，不连接真实车辆、手机、地图、电话或音乐服务。全部规则见 `specification.md`（第 1–18 节原文 + 附录 A 实现时的补充决定）。

## 打开网站

- **直接打开**：双击 `index.html`，用 Chrome、Edge、Safari 或 Firefox 打开即可。不需要安装任何东西，也不需要联网。
- **部署**：把整个文件夹上传到任意静态托管服务（GitHub Pages、Netlify 等）。所有资源都是相对路径。

## 文件

| 文件 | 内容 |
|---|---|
| `index.html` | 页面结构：仪表盘、模拟实体按钮、演示控制 |
| `style.css` | 样式，包括小屏幕上下排列 |

## 页面布局

1. **① 仪表盘**：圆形、底部切平。上方是持续信息区（车速、挡位），中间是页面内容区（弹窗只覆盖这里），底部是保护区（N、ABS、FUEL、已确认警告标记、时钟），永远不被弹窗遮住。仪表盘本身不能点击。
2. **② 模拟实体按钮**：Trip、Page、Home、方向键、OK、Power。当前可用的按钮会高亮，仪表下方同步显示可用操作说明。
3. **③ 演示控制**（紫色虚线框，不属于车辆界面）：车速、来电、普通通知、警告、数据缺失、调试信息、重置演示和演示日志。

## 键盘快捷键

| 按键 | 作用 |
|---|---|
| `X` | Power 开机 / 关机 |
| `H` | Home |
| `P` | Page |
| `T` | Trip |
| `↑` `↓` `←` `→` | 方向 |
| `Enter` | 确认（OK） |

按下并松开算一次，长按不会重复触发。在车速输入框或下拉框里操作时，快捷键不生效。

## 演示步骤（对应说明书第 15 节）

先按 **Power**（或 `X`），等待 3 秒开机，进入首页。

1. 连按五次 **Page**：首页 → 地图 → 媒体 → 车辆 → 设置 → 首页。
2. 在任意页面按 **Home**：回到首页。
3. 在首页按 **Trip**：小窗口依次显示 总里程 → 环境温度 → 预计续航 → Trip A → Trip B → 总里程。
4. 在非首页按 **Trip**：页面和数据都不变（上次输入显示“无操作”）。
5. 切到设置页，在演示控制中点“30”：出现“请停车后操作”；点“停车 0”：提示消失。行驶中仍可用 Home / Page 离开。
6. 点“触发来电”，按 **OK**：只接听，底层页面不变，上方出现“通话中”。用“结束通话”结束。
7. 再次触发来电，按 **下**：只拒接。来电时其他按键全部被忽略。
8. 点“触发短信”，在它消失前点“触发警告”：警告立即替换短信，短信回到队列前方。
9. 按 **OK** 确认警告：短信重新出现并重新计时 5 秒；保护区留下警告标记。
10. 触发通知、来电、警告后按 **Power** 关机，等待 25 秒以上再开机：不会出现任何旧弹窗。

其他可试：“重发上一条（同编号）”不会重复入队；连续触发 7 条消息只保留 5 条等待；勾选“模拟数据缺失”后首页环境温度和车辆页后轮胎压显示“—”；在车速框输入 `abc` 或 `-5` 会被拒绝。

打开“显示调试信息”可以看到当前页面、电源状态、当前弹窗、通知队列、来电和警告状态。“重置演示”恢复到关机初始状态并清除所有计时。

## GitHub 自动备份

自动备份属于开发环境，不在网页里运行；关闭网页不影响它，但电脑关机或休眠时不会执行。

**当前状态：已启用。** 2026-11-02 21:00 验证：测试修改被计划任务自动提交并上传（版本 `6d3cd36`）。 仓库：`https://github.com/zilinzhangzzl/uxdg720-sportster-dash`。脚本不保存任何密码或令牌；登录信息由 Git Credential Manager（Windows 凭据管理器）保存。

### macOS / Linux

1. 在 GitHub 上新建一个**空**仓库（不要勾选添加 README）。
2. 确认能登录：`gh auth login`，或已配置 SSH 密钥。
3. 在项目文件夹中运行：

   ```bash
   bash backup/setup-backup.sh git@github.com:你的用户名/仓库名.git
   ```

   脚本会初始化仓库、首次上传，并安装每 10 分钟运行一次的定时任务。首次上传失败时不会安装定时任务。
4. **验证**：修改任意文件，等最多 10 分钟，在 GitHub 页面看到“自动备份 …”提交后，才算启用成功。

macOS 提示：如果项目放在“文稿”或“桌面”文件夹，cron 可能没有访问权限，需要在“系统设置 → 隐私与安全性 → 完全磁盘访问权限”中加入 `/usr/sbin/cron`，或把项目放到其他文件夹。

停用：`bash backup/setup-backup.sh --uninstall`

### Windows（本项目使用的方式）

1. 安装 Git for Windows（https://git-scm.com），保持默认选项。
2. 在 GitHub 上已建好空仓库 `uxdg720-sportster-dash`。
3. 双击 `backup\setup-windows.bat`。它会：
   - 初始化本地仓库并连接上面的 GitHub 仓库；
   - 首次提交并上传（第一次会弹出浏览器登录 GitHub）；
   - 创建 Windows 计划任务“UXDG720 Sportster Backup”，每 10 分钟在后台隐藏运行 `backup/auto-backup.sh`。
   如果 GitHub 仓库里已有本地没有的内容，脚本会停下，不会覆盖。
4. **验证**：修改任意文件，等最多 10 分钟，在 GitHub 页面看到“自动备份 …”提交后，才算启用成功。

计划任务只在你登录 Windows 时运行；电脑关机或休眠时不会运行，开机后会补一次。

停用：双击 `backup\uninstall-windows.bat`。

### 自动备份的行为

- 每次运行先检查文件；没有变化就不创建版本。
- 有变化时创建一个提交，说明包含时间和变更文件，例如“自动备份 2026-11-02 20:15：更新 1 个文件（style.css）”。
- 上传失败时保留本地提交，写入 `backup/backup.log`，下一次自动重试。
- 里程碑标签上传失败时下次重试；远程已有的同名标签不会被覆盖。
- 远程有本地没有的版本时，停止自动上传，写下 `backup/.backup-paused` 并弹出提示（Windows 上用记事本打开这份说明），不会强制覆盖。手动合并后删除该文件即可恢复。
- 日志、暂停标记和 `.env` 等文件在 `.gitignore` 中，不会上传。演示状态（车速、通知队列）只存在于浏览器内存里，不会被备份。

### 版本存档与命名

每次自动备份都是一个完整的版本存档，GitHub 上不会删除或覆盖旧版本（最小间隔为 10 分钟，10 分钟内的多次修改合并为一个版本）。

重要的里程碑会自动命名：在 `backup/next-tag.txt` 中写入命名请求，下一次自动备份时，脚本会给当时的版本打上标签并上传。请求文件不会被提交，处理后自动删除。

```
v1.0
第一版：老师资料核对前
```

第 1 行是版本名称（只用英文、数字、点和短横线），第 2 行起是中文说明。名称不合规时，请求文件会改名为 `next-tag.invalid.txt` 并写入日志；同名标签已存在时不会覆盖。

命名规则：

| 名称 | 什么时候用 |
|---|---|
| `v1.0` | 第一版，老师资料核对前 |
| `v1.1`、`v1.2` … | 同一阶段内的修正和小改动 |
| `v2.0`、`v3.0` … | 完成一轮重要改动，例如按老师资料改完一轮 |

查看与下载：在 GitHub 仓库页面点 **Tags**（或 Releases → Tags），点某个名称即可查看，或下载那个版本的 ZIP。所有未命名的版本可在 **Commits** 中找到。
